Build a complete, production-ready full-stack web application called **SecurePass — Password Security Coach**.

## 1. PROJECT PROBLEM

Create an application that teaches users about password security and evaluates password practices without storing actual passwords.

The core privacy requirement is extremely important:

**The actual password entered by a user must NEVER be stored, logged, transmitted to the backend, sent to Supabase, sent to analytics, placed in URLs, or exposed in error messages.**

Password evaluation must happen entirely in the user's browser/client side.

Only non-sensitive password characteristics and anonymous results may be stored in Supabase.

The application should be suitable for a college project, demonstration, GitHub repository, and Vercel deployment.

## Password analysis rules

Analyze the password locally using client-side TypeScript.

Check:

- Length
- Uppercase characters
- Lowercase characters
- Numbers
- Special characters
- Repeated characters
- Sequential patterns
- Common weak passwords
- Common patterns such as:
  - password
  - 123456
  - qwerty
  - admin
  - welcome
  - letmein
- Obvious sequences such as:
  - 1234
  - abcd
  - qwerty

Do not claim that this is a perfect security guarantee.

Use labels:

- Very Weak
- Weak
- Fair
- Strong
- Very Strong

Calculate a reasonable security score from 0–100.

Clearly explain that the score is an educational estimate and not a guarantee against cracking.

## CRITICAL SECURITY RULE

Never send the actual password anywhere.

Do NOT:

- send it to an API
- send it to Next.js server actions
- send it to Supabase
- save it in localStorage
- save it in sessionStorage
- save it in cookies
- put it in query parameters
- put it in URL fragments
- store it in React analytics
- log it using console.log
- include it in error messages
- include it in telemetry
- store it in browser history

Keep password analysis entirely in client-side memory.

When the user clears or leaves the page, the password should no longer be retained by application state.

Never hash the password and store the hash either. The requirement is that actual passwords should not be stored.
